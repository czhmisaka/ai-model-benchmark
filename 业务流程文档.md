## 1. 系统概述

### 1.1 系统定位

这是一个**AI模型性能测试平台**，用于：
- 测试多个AI模型的响应速度和质量
- 评估模型输出的准确性、完整性、清晰度等维度
- 生成可视化的测试报告和性能对比

### 1.2 核心功能

| 功能模块 | 说明 |
|---------|------|
| 模型测试 | 支持多模型、多轮次、并发测试 |
| 性能评估 | 测量TTFT、TPFT、Token速度等指标 |
| 质量评估 | 使用AI模型评估输出质量 |
| 定时调度 | 支持定时任务和自动化测试 |
| 结果展示 | Web界面实时展示和历史记录 |
| 数据导出 | 支持Excel、CSV、Markdown格式导出 |

## 3. 详细流程说明

### 3.1 测试配置流程

```
前端界面
    │
    ▼
用户选择:
├─ ✓ 选择模型 (多选)
│     - OpenAI GPT-4
│     - Anthropic Claude
│     - MiniMax M2.7
│     - Google Gemini
│     - Azure OpenAI
│     - 本地模型 (LMStudio)
│
├─ ✓ 选择测试用例
│     - 预设用例 (数学、代码、问答)
│     - 自定义用例
│
├─ ✓ 设置参数
│     - 轮次 (默认 3)
│     - 并发数 (默认 5)
│     - 超时时间 (默认 300s)
│     - 温度 (默认 0.7)
│
└─ ✓ 选择模式
      - 流式输出
      - 非流式输出

    │
    ▼
生成配置 JSON
    │
    ▼
发送到后端 /api/start
```

### 3.2 测试执行流程

```
后端接收配置
    │
    ▼
创建任务:
├─ 生成 group_id (时间戳)
├─ 初始化 Recorder
├─ 创建 ModelClient 实例
└─ 通知前端开始 (SSE event)

    │
    ▼
调度器执行:
for round in range(rounds):
    │
    ├─ 通知轮次开始 (SSE event)
    │
    ├─ 并发执行测试
    │    for model in models:
    │        asyncio.gather(
    │            tester.test_single_request()
    │        )
    │
    ├─ 收集结果
    │
    └─ 通知轮次结束 (SSE event)

    │
    ▼
完成后:
├─ Recorder.finalize()
├─ 生成 summary.json
├─ 发送完成事件 (SSE event)
└─ 通知前端
```

### 3.3 质量评估流程

```
测试结果收集
    │
    ▼
评估器初始化:
├─ 创建 ModelEvaluator
├─ 加载评估 Prompt 模板
└─ 配置评估模型 (通常是更强的模型)

    │
    ▼
评估维度:
├─ 准确性 (accuracy) - 30%
├─ 完整性 (completeness) - 20%
├─ 清晰度 (clarity) - 15%
├─ 相关性 (relevance) - 20%
└─ 格式规范性 (format) - 15%

    │
    ▼
评估执行:
├─ 调用评估模型
├─ 解析 JSON 结果
├─ 计算综合分数
└─ 与参考答案对比 (AnswerComparator)

    │
    ▼
评估结果:
├─ 生成评估报告
├─ 排名模型表现
└─ 保存评估数据
```

### 3.4 数据记录流程

```
测试执行过程中
    │
    ▼
IORecorder 记录数据:
    │
    ├─ 生成 record_id (MD5 hash)
    │
    ├─ 保存到目录结构:
    │    results/
    │    └── {group_id}_{task_name}/
    │         ├── manifest.json        # 任务清单
    │         ├── summary.json         # 汇总统计
    │         ├── all_rounds.md        # Markdown 汇总
    │         │
    │         ├── round_1/
    │         │   ├── {id1}_model1.json
    │         │   ├── {id2}_model2.json
    │         │   └── ...
    │         │
    │         ├── round_2/
    │         │   └── ...
    │         │
    │         └── round_N/
    │              └── ...
    │
    └─ 更新 manifest.json

    │
    ▼
每条记录包含:
├─ id: 记录ID
├─ timestamp: 时间戳
├─ model_name: 模型名称
├─ round: 轮次
├─ success: 是否成功
├─ metrics: 性能指标
├─ prompt: 输入
├─ response: 输出
├─ think_content: 思考内容 (分离)
├─ answer_content: 回答内容 (分离)
└─ evaluation: 评估结果
```

### 3.5 WebSocket/SSE 推送流程

```
后端事件发射器 (TestEventEmitter)
    │
    ▼
事件类型:
├─ task_start    - 任务开始
├─ round_start   - 轮次开始
├─ round_complete - 轮次完成
├─ test_result   - 单次测试结果
├─ progress      - 进度更新
├─ complete      - 任务完成
├─ error         - 错误发生
└─ summary       - 最终汇总

    │
    ▼
前端订阅:
├─ EventSource('/events')
├─ 接收 SSE 事件
├─ 实时更新界面
└─ 展示流式输出

    │
    ▼
心跳机制:
├─ 每 30 秒发送心跳
├─ 保持连接活跃
└─ 检测连接断开
```

### 3.6 定时调度流程

```
定时调度器 (TestScheduler)
    │
    ▼
调度类型:
├─ once     - 单次执行
├─ daily    - 每日执行
├─ weekly   - 每周执行
├─ monthly  - 每月执行
└─ cron     - Cron表达式

    │
    ▼
调度器循环:
while running:
    │
    ├─ 检查所有任务
    │
    ├─ 判断是否到时
    │    next_run <= now
    │
    ├─ 执行任务
    │    execute_task(task_id)
    │
    ├─ 发送 Webhook 通知
    │    - 钉钉
    │    - 飞书
    │    - 自定义 Webhook
    │
    └─ 更新下次执行时间
         next_run = get_next_run_time()

    │
    └─ 等待 check_interval (默认60秒)
```
