# 模型速度测评分析报告

---

## 1. 执行摘要

本次评测针对 **项目构建能力** 这一复杂长输出场景，共测试了五款主流模型：**glm5.2（自费）**、**deepseek-v4-pro**、**mimo-v2.5-pro**、**Minimax-M3**、**gpt-5.5**。所有模型均取得 **10/10 的成功率**，整体可靠性良好，但在任务完成效率上呈现显著分化。

**核心观察**：用户体感最直接的是 **总耗时（从请求到完整回复的等待时间）**，而计费与信息密度取决于 **输出 Token 数量**。一个高效模型必须在这两个维度上同时表现出色，而非单纯追求高 tokens/s 生成速度。

⭐ **任务完成效率最高的模型**：**deepseek-v4-pro**  
它在保证成功完成任务的前提下，实现了 **最短平均总耗时（93.14s）** 与 **第二少的输出 Token 数（6912）**，完美兼顾了“响应快”与“回答精炼”，是本次测评中当之无愧的效率冠军。

**综合表现一句话总结**：
- **deepseek-v4-pro**：又快又省，综合效率最佳 ⭐
- **glm5.2（自费）**：输出最精炼，但生成速度拖慢了总耗时
- **Minimax-M3**：生成速度极快，但输出冗长、Token 消耗大
- **gpt-5.5**：生成速度不慢，但首Token长达21秒，总耗时偏高
- **mimo-v2.5-pro**：总耗时长、输出Token多，效率最低下

---

## 2. 各模型详细分析

### 2.1 deepseek-v4-pro ⭐ 最佳效率

**综合得分与排名**：**第 1 名**（效率冠军）

- **平均总耗时**：**93.144s**（最短 ✅）
- **平均输出 Token**：**6912**（第二少 ✅）
- **综合判断**：总耗时最短 + Token 精炼 → **任务完成效率最高**。用户等待时间最短，且回答几乎没有冗余，是“又快又好”的典范。

**任务完成效率分析**：
- ✅ 平均总耗时比最慢模型 **mimo-v2.5-pro 快 75s**，比第二名 **Minimax-M3 快近 20s**。
- ✅ 平均输出 Token 仅比最少的 glm5.2 多 178 个，信息密度极高。
- ⚠️ 其纯生成速度（76.3 t/s）并非最高，但由于 **输出十分克制**，总耗时大幅缩短，这正是效率模型的最佳体现。

**速度快照**：
- **TTFT（首Token时间）**：平均 **1.302s**（最快 0.654s），响应非常灵敏。
- **TPFT（生成阶段）**：平均 91.82s，纯生成效率 **76.3 t/s**。
- **稳定性**：总耗时波动范围 79.68s ~ 106.53s，抖动不大，表现稳健。

**稳定性分析**：
- 成功率 10/10，所有轮次均顺利完成。
- 输出 Token 最低仅 5226（某些轮次尝试简化但内容略不完整），最高 7574，波动受任务理解影响，但整体总耗时稳定。

**评估结果**：
- 质量评分为 9 分（满分10），大部分回答提供了详尽的开发计划与代码，仅部分轮次因截断或偏离要求扣分，但总体满足长任务需求。

**优势与不足**：
- 优势：总耗时极短、输出精炼、首Token快、稳定性强。
- 不足：少数轮次回答不完整（如轮次7仅输出 HTML 片段），但整体不影响效率评价。

---

### 2.2 glm5.2（自费）

**综合得分与排名**：**第 2 名**（精炼典范，总耗时稍长）

- **平均总耗时**：**128.942s**（中等偏慢）
- **平均输出 Token**：**6734**（最少 ✅）
- **综合判断**：输出 Token 全模型最少，回答极为精炼；但总耗时排名第四，显示出 **生成速度较慢** → ⚠️ 回答精炼但生成速度慢。

**任务完成效率分析**：
- ✅ 输出 Token 最少，节省上下文成本，内容紧凑。
- ❌ 平均总耗时比 deepseek 多出 **35.8s**，用户需多等待约半分钟。
- 虽然总耗时不是最差，但“精炼”未能转化为“总时间短”，说明 **纯生成速度较低**（平均 56.7 t/s），是典型的“内容少但写得慢”。

**速度快照**：
- **TTFT**：平均 **2.212s**，在接受范围内。
- **TPFT**：平均 126.73s，纯生成效率 **56.7 t/s**，为所有模型最低。
- **波动**：总耗时跨度极大，最短 95.4s（轮次7），最长 205.4s（轮次2），稳定性一般。

**稳定性分析**：
- 成功率 10/10。
- 输出 Token 波动 5887 ~ 7978，个别轮次生成篇幅差异大，总耗时剧烈波动。

**评估结果**：
- 大多轮次评分 9 或 10，质量较高，但仍有 3 轮因未完整输出代码被评为不完整或错误。

**优势与不足**：
- 优势：最省 Token，回答直接、代码少废话。
- 不足：生成速度慢导致总耗时偏高，且稳定性不佳。

---

### 2.3 Minimax-M3

**综合得分与排名**：**第 3 名**（生成快但浪费Token）

- **平均总耗时**：**112.603s**（第二快 ✅）
- **平均输出 Token**：**8551**（最多 ❌）
- **综合判断**：总耗时较短，但输出 Token 遥遥领先，存在 **明显冗长和废话输出** → ⚠️ 速度快但不够精炼。

**任务完成效率分析**：
- ✅ 总耗时比 glm5.2 快 16s，比 gpt-5.5 快 8s，用户等待时间尚可。
- ❌ 输出 Token 比最精炼的 glm5.2 多出 **1817 个**，意味着同样的任务产生了大量额外内容，可能拉高 API 费用，且用户阅读负担增加。
- 其纯生成速度高达 76.9 t/s，但被大量输出 Token 拖累，总耗时未能做到极致。

**速度快照**：
- **TTFT**：平均 **1.230s**（最快 0.673s），首字响应顶尖。
- **TPFT**：平均 111.37s，纯生成效率 **76.9 t/s**。
- **稳定性**：总耗时 104.97 ~ 123.20s，波动中等。

**稳定性分析**：
- 成功率 10/10。
- 输出 Token 始终在 8300 以上，几乎不精简，表现出“话痨”倾向。

**评估结果**：
- 多数轮次因截断或部分缺失被评 8~9 分，少部分完全符合要求评 10 分，也有几轮完全偏离任务。

**优势与不足**：
- 优势：总体响应快，首Token极快，生成流畅。
- 不足：输出内容冗余，Token 消耗过高，性价比低。

---

### 2.4 gpt-5.5

**综合得分与排名**：**第 4 名**（首Token严重拖后腿）

- **平均总耗时**：**120.598s**（中游）
- **平均输出 Token**：**7678**（中游偏多）
- **综合判断**：任务完成效率一般，最大硬伤是 **首Token时间极长（21.4s）**，导致总耗时不够短 → ❌ 首字响应极慢，用户体验差。

**任务完成效率分析**：
- ⚠️ 其纯生成速度 77.5 t/s 与 Minimax 相当，但 TTFT 暴增至 21.4 秒，造成总耗时比 Minimax 多 8 秒，比 deepseek 多 27 秒。
- 输出 Token 虽比 glm5.2 多 944 个，但不算特别离谱，效率平平之主因是“思考过久”。

**速度快照**：
- **TTFT**：平均 **21.406s**（最慢可达 45s），严重影响交互体验。
- **TPFT**：平均 99.19s，纯生成效率 77.5 t/s。
- **稳定性**：总耗时 112.7 ~ 136.0s，范围尚可。

**稳定性分析**：
- 成功率 10/10。
- 输出 Token 稳定在 7000~8000，波动小，但首Token时间波动大（13.1~45.0秒），造成部分请求等待近半分钟才开始吐字。

**评估结果**：
- 质量评分普遍 8~10，内容详细，但首Token过长的问题无法忽视。

**优势与不足**：
- 优势：生成速度快，内容质量稳定。
- 不足：首Token等待异常漫长，不适合要求快速反馈的场景。

---

### 2.5 mimo-v2.5-pro

**综合得分与排名**：**第 5 名**（效率最低）

- **平均总耗时**：**168.465s**（最长 ❌）
- **平均输出 Token**：**7941**（次多 ❌）
- **综合判断**：总耗时最长 + 输出 Token 非常臃肿 → ❌ 效率低下，是典型的“写得慢又写得多”。

**任务完成效率分析**：
- ❌ 平均总耗时比最快的 deepseek 多出 **75.3 秒**，用户需要多等一分多钟。
- ❌ 输出 Token 比 glm5.2 多出 1207 个，内容冗余，但耗时却大幅增加，纯生成速度仅 47.7 t/s，是所有模型中最慢的。
- 结论：无论是时间还是 Token，均无优势。

**速度快照**：
- **TTFT**：平均 **1.882s**，尚可。
- **TPFT**：平均 166.62s，纯生成效率 **47.7 t/s**。
- **稳定性**：总耗时 162.4 ~ 191.7s，一直在高位徘徊。

**稳定性分析**：
- 成功率 10/10。
- 输出 Token 在 7000~8600 间波动，整体偏长。

**评估结果**：
- 常因内容截断未完整交付被扣分，多数轮次在 5~9 分之间，说明其虽能生成大量内容但不够完整。

**优势与不足**：
- 优势：输出篇幅长，尝试覆盖全面。
- 不足：生成速度最慢，总耗时最长，Token 使用不经济，综合体验最差。

## 3. 对比分析

### 各模型任务完成效率对比表

以下表格直接呈现 **平均总耗时** 与 **平均输出 Token 数** 两项核心效率指标，**越短/越少代表效率越高**。

| 模型             | 平均总耗时（s） ⏱️ | 平均输出 Token 🔢 | 纯生成速度 (t/s) | TTFT 平均 (s) | 效率评级      |
|------------------|-------------------|-------------------|------------------|---------------|---------------|
| deepseek-v4-pro  | **93.14** ⭐      | **6912**          | 76.3             | 1.30          | ✅ 最高效      |
| Minimax-M3       | 112.60            | 8551 ❌           | 76.9             | 1.23          | ⚠️ 快但啰嗦   |
| gpt-5.5          | 120.60            | 7678              | 77.5             | 21.41 ❌      | ❌ 首字太慢   |
| glm5.2（自费）   | 128.94            | 6734 ⭐           | 56.7             | 2.21          | ⚠️ 精炼但慢   |
| mimo-v2.5-pro    | **168.47** ❌     | 7941 ❌           | 47.7             | 1.88          | ❌ 效率最低   |

**关键区分**：
- **最快输出模型（tokens/s 最高）**：gpt-5.5 与 Minimax-M3 并列 ~77 t/s，但它们的总耗时并非最短，因为一个首Token极慢，一个输出Token过多。
- **最佳效率模型（总耗时短 + Token少）**：deepseek-v4-pro，其总耗时远低于其他模型，而输出 Token 仅略高于最精炼的 glm5.2，是真正的“好钢用在刀刃上”。

### 不同测试用例下的表现差异
所有模型均执行同一套复杂的“生成完整项目开发计划与代码”提示词。**deepseek-v4-pro** 在几乎每一轮都能保持 **80~106s 的总耗时**，且输出长度克制；而 **mimo-v2.5-pro** 几乎轮轮耗时超过 160s，且大量 Token 消耗在未完成或冗余的代码上。**glm5.2** 虽然生成了最少的 Token，但某些轮次生成速度突然变慢（如轮次1、2长达200s），反映出速度稳定性问题。

## 4. 选型建议

- **追求“用户体感最好的响应速度”** → 选择 **deepseek-v4-pro**。总耗时最短，用户从发送请求到拿到完整结果只需约 1.5 分钟，比最慢模型快 75 秒，且回答简洁。

- **追求“性价比（按 Token 计费）”** → 选择 **glm5.2（自费）**。输出 Token 最少，平均每轮仅 6734 Token，若按输出计费可显著节省成本。需注意其总耗时偏长，适合对延迟不敏感但关注成本的批处理场景。

- **追求“又快又省的综合效率”** → 依旧 **deepseek-v4-pro** 是最佳选择，它同时具备最短总耗时和第二少的输出 Token，在时间和费用之间取得了完美平衡。

- **追求“首 Token 响应快”** → 可考虑 **Minimax-M3**（平均 TTFT 1.23s）或 **deepseek-v4-pro**（1.30s），两者首字反馈均极快，适合需要快速流式展示的应用。但需容忍 Minimax 的冗长输出。

- **不同场景下的最佳选择**：
  | 场景                   | 推荐模型          | 理由                           |
  |------------------------|-------------------|--------------------------------|
  | 实时交互/聊天助手      | deepseek-v4-pro   | 总耗时短，首Token快，体验流畅 |
  | 批量离线生成/成本敏感  | glm5.2（自费）    | 输出Token最少，API 费用最省     |
  | 长篇幅报告需大量细节   | Minimax-M3        | 生成速度快，内容详尽           |
  | 对完整度要求极高       | deepseek-v4-pro   | 完整度高的同时效率卓越         |
  | 避免选择               | mimo-v2.5-pro / gpt-5.5 | 前者效率过低，后者首Token等太久 |

## 5. 结论

**最终一句话**：在“又快又好地完成项目构建任务”这一要求上，**deepseek-v4-pro 以最短总耗时和高度精炼的输出，夺得了任务完成效率的冠军** ⭐，是本次测评中毫不犹豫的首选模型。

**最终推荐与理由**：
- 无论从开发者体感（等待时间）、计费经济性（输出Token量）还是任务成功率来看，**deepseek-v4-pro** 都给出了教科书级的效率表现。它用不到 94 秒生成了约 6900 个高质量 Token，既无冗余，也未在生成速度上虚高，是“少即是多”的最佳实践。
- 如果您的业务对成本极度敏感且允许稍长的响应时间，可考虑 **glm5.2（自费）** 作为降本方案；但若想获得真正的流畅体验与综合收益，deepseek-v4-pro 仍然是那个最稳妥、最高效的答案。
